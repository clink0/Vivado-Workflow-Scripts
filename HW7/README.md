# HW7 — Serial Peripheral Interface (SPI)

## Overview

HW7 has two tasks:

| Task | What it does |
|------|-------------|
| **T1** | SPI loopback — leader sends `sw[7:0]` to an internal follower on button press; `led[7:0]` shows what was received |
| **T2** | Smart Light Controller — PicoBlaze reads the PmodALS ambient light sensor via SPI and drives `led[15:0]` (brighter room = fewer LEDs) |

---

## What You Need

### T1 — No external hardware
Just the Basys 3 board.

### T2 — PmodALS sensor
- Basys 3 board
- Digilent PmodALS ambient light sensor
- 4 jumper wires

## Task 1 — SPI Loopback

### Step 1: Build

From the **repo root** in PowerShell:

```powershell
.\HW7\T1\build.ps1
```

This runs `run_hardware.py` which synthesizes, implements, and writes the bitstream. Wait for it to finish (~3-5 min).

### Step 2: Program the board

1. Open **Vivado Hardware Manager**
2. Click **Open Target → Auto Connect**
3. Click **Program Device**
4. Bitstream is at:
   ```
   HW7\T1\vivado_project\T1.runs\impl_1\spi_top.bit
   ```
5. Click **Program**

### Step 3: Test

| Action | Expected result |
|--------|----------------|
| Set `sw[7:0]` to any pattern (e.g. `10110101`) | — |
| Press **btnR** (right button) | `led[8]` (leader busy) flickers briefly |
| Release btnR | `led[7:0]` shows the **same pattern** as the switches |
| Change switches, press again | `led[7:0]` updates to new value |

`led[9]` pulses when the follower finishes receiving. It is a 1-cycle pulse so it may not be visibly on.

**What to show for demo:** Set a recognizable switch pattern, press btnR, show LEDs match the switches.

## Task 2 — Smart Light Controller

### Step 1: Wire the PmodALS

Plug the PmodALS into the **JB** header using **individual jumper wires** (do not plug the module directly — the SCK position does not match the standard Pmod pinout):

| Basys 3 JB pin | PmodALS pin | Signal |
|----------------|-------------|--------|
| JB1 (top-left) | /CS | Chip select (active low) |
| JB2 | SDO | Serial data out (MISO) |
| JB3 | SCLK | Serial clock |
| JB GND (pin 5) | GND | Ground |
| JB VCC (pin 6) | VCC | 3.3V power |

> **Important:** VCC on the JB header is 3.3V. Do NOT connect the PmodALS to the 5V rail — it is a 3.3V device.

The JB header is on the bottom-left of the Basys 3 board. The top row has pins 1–4 (signals) and the bottom row has GND (pin 5) and VCC (pin 6) at the left end.

### Step 2: Build

From the **repo root** in PowerShell:

```powershell
.\HW7\T2\build.ps1
```

This script does three things automatically:
1. Copies `ROM_form.v` from `Lab8/kcpsm6_files/`
2. Runs `kcpsm6.exe` to assemble `als_rom.psm` → `als_rom.v`
3. Runs `run_hardware.py` to build and generate the bitstream

Wait for it to finish (~5-8 min). If it prints `ERROR: als_rom.v was not generated`, the assembler failed — check that `Lab8/kcpsm6_files/kcpsm6.exe` exists.

### Step 3: Program the board

1. Open **Vivado Hardware Manager**
2. Click **Open Target → Auto Connect**
3. Click **Program Device**
4. Bitstream is at:
   ```
   HW7\T2\vivado_project\T2.runs\impl_1\als_top.bit
   ```
5. Click **Program**

### Step 4: Test

| Condition | Expected LED behavior |
|-----------|----------------------|
| Normal room lighting | ~8–12 LEDs on |
| Cover the sensor completely (dark) | All 16 LEDs on |
| Shine a flashlight / phone flashlight at sensor | Fewer LEDs on — could go to 1–2 |

The LEDs update approximately every 100ms (SPI triggers every 10 million clock cycles).

**Logic:** The PicoBlaze takes `light_val >> 4` (0–15 shifts) and right-shifts `0xFFFF` that many times. Higher light → more shifts → fewer LEDs lit.

**What to show for demo:** Cover the sensor (all LEDs on), then uncover/shine light (LEDs reduce). The gradual change shows the sensor is being read correctly.

## Key SPI Concepts for Report

### T1 — SPI Mode 0 (CPOL=0, CPHA=0)
- SCK idles **low**
- Leader puts data on MOSI at **falling edge** of SCK
- Follower samples MISO/MOSI at **rising edge** of SCK
- SS goes low to start, high when done

### T2 — SPI Mode 3 (CPOL=1, CPHA=1)
- SCK idles **high** (required by ADC081S021)
- CS goes low while SCK is high (Mode 3 requirement)
- Data is sampled on **falling edge** of SCK
- 16-bit packet: `[000][8 data bits][0000]` — extract bits `[11:4]` for the 8-bit value

### PicoBlaze LED computation
```
n = light_val >> 4          ; 0-15 (how many LEDs to turn off from MSB)
led = 0xFFFF                ; start all on
repeat n times:
    sr0 led_msb             ; shift 0 into bit 15
    sra led_lsb             ; shift MSB of led_msb into bit 7
```

## Troubleshooting

| Problem | Likely cause | Fix |
|---------|-------------|-----|
| `als_rom.v was not generated` | Assembler failed | Check `Lab8/kcpsm6_files/kcpsm6.exe` exists; check `als_rom.psm` for syntax errors |
| LEDs all stay on in T2 | Sensor not receiving data | Check JB1=CS, JB2=SDO, JB3=SCK wiring; confirm GND and VCC connected |
| LEDs all off in T2 | SPI data corrupted | Re-check Mode 3 wiring; ensure common GND between board and sensor |
| Pressing btnR does nothing in T1 | Button debounce / `send_latch` not firing | Hold button for ~0.5s; rebuild if issue persists |
| Bitstream not found after build | Synthesis/impl error | Check `HW7/T1/vivado.log` or `HW7/T2/vivado.log` for errors |
